This page provides a list of the FHIR artifacts defined as part of this implementation guide.

Behavior: Capability Statements

The following artifacts define the specific capabilities that different types of systems are expected to have in order to comply with this implementation guide. Systems conforming to this implementation guide are expected to declare conformance to one or more of the following capability statements.

Paramedic Handover Receiver

Server capabilities an emergency department FHIR server needs to accept paramedic handovers and run the admissions review queue.

Structures: Resource Profiles

These define constraints on FHIR resources for systems conforming to this implementation guide.

Handover Admit Task

Work item asking ED admissions to verify identity, confirm SNOMED codings and admit.
Handover Transcript

Verbatim transcript of the spoken IMIST-AMBO handover, kept for audit.
Paramedic Handover Bundle

Transaction bundle committed at handover: one patient, one encounter, the admit task and the transcript, plus coded findings.
Paramedic Handover Encounter

Emergency encounter created when a paramedic hands a patient over to the ED.

Structures: Extension Definitions

These define constraints on FHIR data types for systems conforming to this implementation guide.

Handover Source Section

The IMIST-AMBO section of the spoken handover that a coded item was extracted from.

Terminology: Value Sets

These define sets of codes used by systems conforming to this implementation guide.

IMIST-AMBO Handover Sections

All IMIST-AMBO handover sections.

Terminology: Code Systems

These define new code systems used by systems conforming to this implementation guide.

Handover Task Codes

Local workflow codes for ED handover processing.
IMIST-AMBO Handover Section

Sections of the IMIST-AMBO clinical handover mnemonic.
